# Subject requirements

A requirement is a scoped proposition. It is not automatically an earlier operation. Necessary case specification, successful operation conditions, quality conditions, method prerequisites, justification requirements, and conditions under study have different force. These 39 records are an examined subset; requirements for every catalog subject are not yet exhaustively derived.

## Separating cases

| Case | Situation | Consequence |
|---|---|---|
| Empty choice | A selector has no identifiable candidate. | Reasoning approach selection cannot successfully complete; Reasoning approach availability can correctly return none. |
| One candidate | A user directly supplies one applicable approach. | Selection is possible without a search, comparison ranking, or prior repository lookup. |
| Construct then choose | A workflow constructs an approach before choosing it. | Creation precedes this choice in this case; candidates need not preexist the whole workflow. |
| Available but unnoticed | A usable approach is accessible but the agent fails to recognize it as a candidate. | Availability, identification and actual use remain different determinations. |
| Available but unusable here | The selector can inspect an approach whose input assumptions fail in the live case. | Availability does not imply applicability or successful execution. |
| Available but unauthorized action | An approach specification is readable; an execution action lacks required permission. | Specification access does not supply execution authorization. |
| True without evidence | A precise claim happens to be true although the assessor has no supporting information. | Truth and warranted acceptance have different requirements. |
| Consistently wrong proxy | A measurement returns stable scores unrelated to the target property. | Repeatability does not establish proxy validity. |
| Same operation, different target | A SAT selector chooses an executable solver; a motor task selects a physical response. | Shared selection structure permits analogy but not subject or mechanism identity. |
| Same word, different mechanism | A model computes attention weights; a person sustains attention during a task. | Lexical identity does not establish computational or neural equivalence. |
| Route without finite optimum | A graph permits ever cheaper walks through a reachable negative cycle. | A route can exist without an attained minimum under that walk definition. |
| Legal but ineffective | A correctly authorized rule produces none of its intended benefits in a measured case. | Authority, compliance and causal effectiveness are separate matters. |
| Precise false claim | A specified scalp feature is claimed to predict a specified trait in a declared population. | The relation is a real investigable subject even if the predictive claim fails. |
| Retention loses utility | Additional retained records increase retrieval effort enough to reduce later usable benefit. | Retention quantity is not the objective; cost and future use need comparison. |
| Rare name, common work | A new subject label describes part of an existing solver-selection literature. | Missing from this catalog does not establish neglect in the world. |
| Partial translation | Plot is mapped only to presentation order. | The translation leaves causal organization and other intended readings uncovered; record the residual. |
