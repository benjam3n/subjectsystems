Specified systems as designed artifacts, including custom descendants, interfaces, or observed executions.

## System identity

| Subject | Definition | Exclusion |
|---|---|---|
| System identity specification | Specify which artifact or version constitutes the named system. | Inferring a source identity from a similar project name. |
| System identity lineage | Establish the sources and deliberate departures that define a custom descendant. | Attributing the descendant's new operations to the original source. |

## System purpose

| Subject | Definition | Exclusion |
|---|---|---|
| System purpose specification | Specify the subject and result for which this particular system is being developed. | Treating relevance to a broad topic as a complete local design. |

## System design

| Subject | Definition | Exclusion |
|---|---|---|
| System design creation | Construct a purpose-specific system specification with actual objects, operations, and results. | Creating an empty directory or renamed source reference. |
| System design modification | Revise an identified system design with the changed behavior explicit. | Claiming the revision was implemented or effective without evidence. |
| System design composition | Construct a system arrangement whose intermediate results have explicit consumers. | Linking several project READMEs without a functioning design relation. |

## System interface

| Subject | Definition | Exclusion |
|---|---|---|
| System interface contract | Specify the content, conditions, and failure meanings exchanged by identified system components. | Inferring compatibility from matching field names. |
| System interface compatibility | Determine whether a producer's specified output satisfies a consumer's specified input contract. | Declaring every interface question a collection of unrelated subjects. |
| System interface failure propagation | Determine which dependent results are affected by a specified interface failure. | Invalidating independent results without a dependency. |

## System implementation

| Subject | Definition | Exclusion |
|---|---|---|
| System implementation correspondence | Determine which behaviors of the specified design the implementation actually realizes. | Equating the written design with running behavior. |
| System implementation execution evidence | Identify which observed execution supports each specified implementation claim. | Treating a README demonstration as a verified run here. |

## System composition

| Subject | Definition | Exclusion |
|---|---|---|
| System composition order dependence | Determine which changes of component execution order change a specified system result when the components and input are fixed. | Differences caused by adding components, changing their implementations or changing the input. |
| System composition description sufficiency | Determine whether a specified description fixes the system properties needed for an identified task, or whether two realizations satisfy it while differing on those properties. | Assuming a set of topics specifies causal order, interfaces or stopping behavior. |
