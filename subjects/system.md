Specified systems as designed artifacts, including custom descendants, interfaces, or observed executions.

## System identity specification

Which artifact or version constitutes the named system. Excludes: Inferring a source identity from a similar project name.

## System identity lineage

Establishment of the sources and deliberate departures that define a custom descendant. Excludes: Attributing the descendant's new operations to the original source.

## System purpose specification

The subject and result for which this particular system is being developed. Excludes: Treating relevance to a broad topic as a complete local design.

## System design creation

Construction of a purpose-specific system specification with actual objects, operations, and results. Excludes: Creating an empty directory or renamed source reference.

## System design modification

Revision of an identified system design with the changed behavior explicit. Excludes: Claiming the revision was implemented or effective without evidence.

## System design composition

Construction of a system arrangement whose intermediate results have explicit consumers. Excludes: Linking several project READMEs without a functioning design relation.

## System interface contract

The content, conditions, and failure meanings exchanged by identified system components. Excludes: Inferring compatibility from matching field names.

## System interface compatibility

Whether a producer's specified output satisfies a consumer's specified input requirements. Excludes: Declaring every interface question a collection of unrelated subjects.

[System description examination](../systems/system-description-examination.md)

## System interface failure propagation

Which dependent results are affected by a specified interface failure. Excludes: Invalidating independent results without a dependency.

## System implementation correspondence

Which behaviors of the specified design the implementation actually realizes. Excludes: Equating the written design with running behavior.

[System description examination](../systems/system-description-examination.md)

## System implementation execution evidence

Which observed execution supports each specified implementation claim. Excludes: Treating a README demonstration as a verified run here.

## System composition order dependence

Which changes of component execution order change a specified system result when the components and input are fixed. Excludes: Differences caused by adding components, changing their implementations or changing the input.

[Mind change selection](../systems/mind-change-selection.md)

## System composition description sufficiency

Whether a specified description fixes the system properties needed for an identified task, or whether two realizations satisfy it while differing on those properties. Excludes: Assuming a set of topics specifies causal order, interfaces or stopping behavior.
