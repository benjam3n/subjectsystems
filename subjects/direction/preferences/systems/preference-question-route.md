# Preference question route

Subject: [Preferences](../README.md).
Source families: [QuestionRoute](../../../../systems/questionroute.md).
Standing: specified design, version 0.1. Prospective effectiveness is unestablished.

## Local purpose

Choose and continue a preference inquiry according to what its possible answers would distinguish.

## What changes from the source

Specialize routes and predicted-answer continuations to contextual preference hypotheses. Preserve ties, incomparable candidates, rejection of both, and changes of context as meaningful branches. Repeated questioning is not treated as accumulating truth or calibrated confidence.

## Objects and distinctions

Preference question; candidate answers; conditional hypotheses; diagnostic contrasts; actual answer; typed follow-up relations; unresolved context.

## Operations

1. Start from a consequential unresolved distinction in the preference account. Construct alternative questions if the current wording presupposes the disputed preference.
2. For each candidate question, construct plausible answer branches, including neither, both, tie, context-dependent, and unable-to-judge where relevant. These are anticipated possibilities, not observations.
3. Derive which hypothesis or contextual distinction each answer would change. Replace a question whose answers all leave the live distinction unchanged.
4. Choose a question for the distinction needed by the receiving task. Use an already recorded answer when it actually addresses that question; otherwise seek only the necessary missing judgment.
5. After an actual answer, follow the corresponding clarification, opposition, concretization, or other justified route. Preserve alternatives that the answer did not distinguish.
6. Revise the question when its assumptions were rejected. Return a new discriminator or a contextual account that is sufficient for the receiving use.

## Result and consumer

An inquiry route whose continuations depend on actual answers, with the preference distinction it addresses kept explicit.

## Quality and defeating case

A linear questionnaire that ignores an answer-dependent difference fails the local purpose. An anticipated answer must not be stored as the person’s response.

## Continuation

Pass the answer and context to Preference discovery or another local consumer. Continue only where the next distinction bears on the work.

## Illustrative distinction

If both names are rejected because they imply a finished product, the next question concerns that shared implication. Asking which of the two is prettier repeats a presupposition the answer already rejected.

The example illustrates the specification. It is not a prospective performance result.
