Actual control states of an adopted activity, with its substantive result kept distinct.

## Execution state initiation

The grounds establishing that the specified authorized activity actually began. Excludes: Reporting intention to begin.

## Execution state progress

Which specified activity conditions have been completed so far. Excludes: Inferring completion from elapsed time.

## Execution state interruption

The point and conditions at which ongoing activity ceased temporarily. Excludes: Treating interruption as withdrawal of authorization.

## Execution state resumption

Reestablishment of the interrupted activity from its consequential current state. Excludes: Repeating completed work by default.

## Execution state completion

Whether the specified activity's completion conditions were met. Excludes: Claiming the larger goal was achieved merely because the activity ended.

## Execution state termination

The grounds establishing that further execution has ended under its stated stopping condition. Excludes: Conflating termination with successful completion.

## Execution record correspondence

Whether the execution record matches the operations actually performed. Excludes: Treating a written procedure as a run record.

## Execution record comparison

Comparison of specified executions under fixed input and outcome definitions. Excludes: Claiming causal superiority from uncontrolled differences.

## Execution record representation

Representation of the actual run identity, inputs, performed operations, and results. Excludes: Implying that a well formed record verifies its own factual accuracy.
