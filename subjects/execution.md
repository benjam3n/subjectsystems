Actual control states of an adopted activity, with its substantive result kept distinct.

## Execution state

| Subject | Definition | Exclusion |
|---|---|---|
| Execution state initiation | Establish that the specified authorized activity actually began. | Reporting intention to begin. |
| Execution state progress | Determine which specified activity conditions have been completed so far. | Inferring completion from elapsed time. |
| Execution state interruption | Identify the point and conditions at which ongoing activity ceased temporarily. | Treating interruption as withdrawal of authorization. |
| Execution state resumption | Reestablish the interrupted activity from its consequential current state. | Repeating completed work by default. |
| Execution state completion | Determine whether the specified activity's completion conditions were met. | Claiming the larger goal was achieved merely because the activity ended. |
| Execution state termination | Establish that further execution has ended under its stated stopping condition. | Conflating termination with successful completion. |

## Execution record

| Subject | Definition | Exclusion |
|---|---|---|
| Execution record correspondence | Determine whether the execution record matches the operations actually performed. | Treating a written procedure as a run record. |
| Execution record comparison | Compare specified executions under fixed input and outcome definitions. | Claiming causal superiority from uncontrolled differences. |
| Execution record representation | Represent the actual run identity, inputs, performed operations, and results. | Implying that a well formed record verifies its own factual accuracy. |
