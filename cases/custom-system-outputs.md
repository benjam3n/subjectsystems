# Different systems, different results from one episode

Standing: retrospective design demonstration using the recorded naming conversation. The observations already occurred; the three local specifications were written afterward. This is not a prospective comparison or new user feedback.

## Shared observations

The user said the candidates should remain general but claim less. System Kit received a positive judgment. The user then requested a name claiming less than kit, proposed subjectsystems, accepted that direction, and authorized repository setup.

These observations can be shared by several local systems. Their results are different.

## Preference discovery result

The explicit preference for this task is a general name with a lower claim than Kit. System Kit's positive reception and later displacement remain separate observations. The accepted Subject Systems name supplies a final selection in this episode.

A hypothesis that the user always rejects toolkit names is unsupported. A hypothesis that every feature of Subject Systems was individually preferred is also unsupported. No further comparison or user response has been obtained to establish either claim.

The result is contextual preference evidence and limits on inference. It is not a designed repository or a claim that the chosen architecture is effective.

## Goal discovery result

The naming goal is to identify the undertaking with a simple, literal entity name that remains general while making a modest claim. The substantive project goal remains developing subjects and their systems deeply. The restriction on claims in the name does not lower that intellectual goal.

Achievement of the naming choice and achievement of the project's intellectual aims are distinct. The selected name can satisfy the former while the subject sciences remain undeveloped.

The result is a distinction between the purposes and their conditions of achievement. It is not a new observation of preference or evidence that the intellectual goals have been attained.

## Design exploration result

The name chosen for the repository is Subject Systems. The repository arrangement is a second design object that can change while that name stays fixed. The later user request changes this arrangement toward custom systems within each subject.

The concrete revised design uses local files under `subjects/<group>/<subject>/systems/`, with separate purposes and operations and a reference to the original family. Preferences receives a diagnostic selection procedure; Goals receives candidate aims and criterion development; Design receives artifact exploration and feasibility work.

The result is a concrete arrangement that has been specified in this revision. Prospective effectiveness of the local procedures is unestablished.

## A difference in continuation

| Local system | What could make the next step useful |
|---|---|
| Preference discovery | A consequential choice needs a distinction between still-live preference hypotheses |
| Goal discovery | A new candidate aim reveals that an achievement condition was only a favored means |
| Design exploration | A prototype exposes a feasibility problem or reveals a missing requirement |

Giving all three systems the same instruction to generate more attractive examples could miss these differences. A local version must change the work where its purpose requires it.
