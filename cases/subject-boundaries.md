# Boundary cases for the scope model

Standing: Constructed cases and analysis of the retained naming episode, reviewed while deriving the working definitions. These are reasoning checks, not independent empirical validation or a proof covering every possible matter.

## Same artifact, different matter

| Case | Determinations and placement | Why this is a distinction rather than an arbitrary home |
|---|---|---|
| A false but definite meeting time; a true weather statement | Requested kind of answer: Q2. Truth of the meeting or weather claim: its substantive inquiry. Grounds: A2. | Fit and truth vary independently. Supplying a value of the requested kind does not establish that it is the right value. |
| New wording for the same meeting question; identical wording about a different meeting | Question identity: Q1. Textual arrangement once the content is identified: E1. | The requested distinction and referent can remain fixed under new wording or change under identical wording. Merely detecting different strings cannot settle identity. |
| A question about which goal to pursue | Specification of the question: Q1. Intended achievement conditions: P1. Comparative merit: V3. Adoption of pursuit: P2. | Using an interrogative sentence does not make every matter it asks about a study of questions. The answer's actual determination decides its scope. |
| A question recovered from an old notebook | Continuity with the earlier item: M1. Novelty to this investigation: M2. Creation or identity of the question: Q1. | The question can be old and newly available at once. The same wording may also fail to preserve its original referent; these are independently variable relations. |
| A plan also called a strategy | The same course structure: R3. | No discriminating property has been supplied. The two labels are merged in this shared sense instead of using a preferred name to fabricate exclusivity. |
| A route of questions about preferences | Each requested distinction: Q1. Branching after answers: R3. Descriptive preference result: V1. | The route can change while its questions retain their identity; a new preference finding can change which route is useful. The source name QuestionRoute does not determine all three scopes. |
| Liking, endorsing, and adopting a repository name | Observed favoring: V1. Reasons for a standard: V2. Merit under it: V3. Adoption: P2. | A name can be favored but unavailable, satisfy a standard without being adopted, or be adopted despite a compromise. These are not interchangeable results. |
| A goal and a plan written in one paragraph | Intended outcome: P1. Means and contingencies: R3. Expression: E1. | A plan can change without changing its intended outcome. A rewrite can preserve both. The paragraph is a container, not the unit being partitioned. |
| A prompted response that is fluent but follows the wrong instruction | Textual arrangement: E1. Attributed instruction interpretation: E2. Answer fit: Q2. Actual execution: T2. Relevant underlying task: its substantive scope. | Fluency does not establish interpretation or answer fit. The recipient can understand the instruction and still fail to carry it out. |
| An explanation that also predicts | Explanatory contrast and dependence: A3. Forecast and outcome relation: A4. Support for the account: A2. | One account can have two uses. Whether it addresses a why-question and whether its prior forecast matches an outcome are different relations. Neither use proves the account well supported. |
| A supported claim recorded as uncertain; an unsupported claim recorded as certain | Grounds: A2. Represented epistemic position: A5. | Acceptance and warrant can diverge. A certainty label cannot establish support. |
| A stored false statement; a correctly recalled but unusable explanation | Retention and recovery: M1. Support: A2. Usable capability: B1. | Storage does not certify truth. Recall does not establish an ability to use the recovered relation in a new case. |
| Learning that worsens performance; improvement by repairing an artifact | Experience-dependent change: B2. Comparative benefit: V3. | The cause of a change and its merit are independently variable. Learning and Improvement cannot be exhaustive, exclusive kinds of change. |
| A completed file move that leaves the original problem unresolved | Operation completion: T2. Adequacy of the specified result to the problem: R2. | The move may satisfy every condition of the operation while leaving a necessary goal condition unsatisfied. |
| A file that can be retrieved but cannot be used within a proposed configuration | Retention/recovery: M1. Configuration feasibility: R4. Focus on retrieved content: T1. | Recoverability, feasibility of a larger arrangement, and actual attention can change independently. Calling the file a resource settles none of them. |

## Actual collision found and repaired

An initial draft defined R2 broadly as whether an intervention produces a target change. That scope would also admit an instruction's effect on an addressee and an experience-induced update. Simply calling the first “communication” and the second “learning” would not exclude the same matter from R2.

R2 is therefore **remedy adequacy**: given a specified change and effect account, does that effect address the identified obstruction and achievement conditions? E2 concerns the interpretation attributed to the addressee and its correction within an interaction; Q2 concerns answer fit and T2 actual execution. B2 concerns the agent's experience-dependent update. Whether the stipulated effect actually occurs must be established in the relevant target inquiry; R2 does not silently certify it.

For example, assume a change makes every old file retrievable. That effect can remedy missing access while remaining insufficient to remedy failure to use available corrections. This adequacy question can be settled while the causal explanation of how access was improved remains unchanged or unknown.

This is a substantive narrowing with a consequence. A system using R2 must expose its assumed effect and cannot treat a remedy's conceptual adequacy as evidence of successful execution or causation.

E2 also needed narrowing: a broad instruction-compliance definition would duplicate Q2 whenever the instruction asks a question. Its implemented scope concerns attributed interpretation and communicative alignment. Correct interpretation can coexist with a nonresponsive answer or failed execution, and an answer can happen to fit without establishing how it was interpreted. This removes compliance as a competing general owner of answer fit.

## Generality and target-specific construction

| Matter | Placement | Exclusion that matters |
|---|---|---|
| How to construct a question with a stated distinction and answer conditions | Q1, within question specification | G2 does not receive every local construction because it studies general intellectual operations. |
| How to construct a goal's achievement conditions | P1 | Its output is an intended outcome specification, not a question merely because questions are used to form it. |
| What a general candidate-generation operation preserves when its target kind changes | G2 | Its answer ranges across target kinds under stated conditions; it does not replace the local question or goal result. |
| What follows formally from composing a necessary dependency with a merely helpful contribution | G1 | The issue is the relation predicates and licensed composition, not every fact about the objects standing in them. |
| How selection of a concrete candidate can justify a design requirement across artifact kinds | G3 | The general form–requirement relation is being considered. The exact artifact still needs its target scope. |
| Which keyboard and focus behavior a particular new repository interface must implement | A missing target-specific interface scope | E1 may contribute representation and R4 feasibility, but neither defines the whole specified interaction contract. General Design is not an automatic home. |

A general principle can be discovered through a local case. That does not make the local result and generalization identical. State the target range claimed by the answer. “General” is neither a prestige label nor a destination for matters the atlas cannot classify.

## When separation is legitimate

An inquiry can request several independently assessable results: formulate a goal, justify a criterion, and adopt a course. The composite system can coordinate them while retaining their separate determinations.

A request can also ask about one coupling relation. “Can a proposed interface retain these identities while satisfying this exact interaction contract?” is not automatically two unrelated questions about identity and communication. The compatibility relation itself needs an adequate scope. If the existing definitions do not admit it, define that missing matter; if two definitions admit exactly that relation, repair or merge them. A cross-link, “primary purpose,” or the word composite does not resolve the defect.

The same distinction applies to broad research programmes. A programme may coordinate several scopes and can be studied as an investigative practice in N1. This does not make all of its contents N1 matters.

## Review result and remaining exposure

The cases support specific separations, the Planning/Strategy merge, and the narrowing of R2. They also expose an honest coverage gap for new target-specific interface work. The working model is suitable for continued development of the identified material; these examples do not prove pairwise exclusion over every interpretation of every definition.

The next boundary work should use an actual new task and its exact required result. A real single-matter collision is evidence to change the definitions. Merely using several source systems on one task is not such a collision.
